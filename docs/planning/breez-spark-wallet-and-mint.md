# A home Breez Spark wallet, a Goats Cashu mint and a selectable payment backend

**Host-agent handoff · 2026-11-19.** Build the wallet on `10.8.0.6` first, the mint second, and the Goats integration third. The operator assigns each stage when ready. Publication is a planning action. Production stays on Strike during infrastructure work.

| Order | Owner | Deliverable |
|---|---|---|
| [1. Wallet](#1-home-wallet) | HOME on `10.8.0.6`, with one VPS connectivity check | One private, persistent Breez Spark service that can issue and settle Lightning invoices. It becomes the mint’s reserve wallet. |
| [2. Mint](#2-home-mint-and-vps-ingress) | HOME owns issuance and reserves. VPS owns the public HTTPS endpoint. | A working sat-denominated mint tested with independent wallets, including Minibits, before Goats calls it. |
| [3. Application](#3-repository-and-vps-integration) | Repository agent implements. VPS agent stages. | A single setting selects Strike or Breez for new work. Under Breez, the project holds its earnings in Goats-issued ecash. |
| [4. Cutover](#4-vps-cutover-and-rollback) | VPS and HOME, at the operator’s chosen time | Reconciled live receipts, a mixed-payment feed, operator access through Minibits, and a tested route back to Strike. |

### What belongs to whom

The **mint reserve** holds the underlying sats that back outstanding Goats tokens, including tokens held by viewers. The **Goats collection wallet** owns the project’s tokens. The existing CDK receiver and core stay together on the VPS, where local Unix peer credentials authenticate credit receipts. The **operator’s Minibits wallet** has its own keys and can receive and spend the project’s available earnings. Adding the mint URL to the phone starts with the tokens that phone owns. Give it an explicit transfer to make earnings available there. Keep mint signing, reserve spending and the automated collector’s keys out of the phone. [Goats wallet/core boundary](../architecture/cashu-wallet-boundary.md) · [Minibits wallet](https://github.com/minibits-cash/minibits_wallet)

| Event in Breez mode | Money movement | Feeder effect |
|---|---|---|
| Viewer buys tokens for their own wallet | Lightning enters the reserve. The viewer claims the tokens. | Zero credit. |
| Viewer pays a herd/goat Lightning address or NIP-57 zap invoice | Lightning enters the reserve once. The project claims a mint quote owned by the collection wallet. | One donation, credited once after the settled invoice and project-owned proofs reconcile. |
| Ordinary Cashu or NIP-61 nutzap from the Goats mint | The collector swaps the sender’s proofs for fresh, verified proofs it owns. The reserve stays in place. | One donation. |
| Ordinary Cashu or nutzap from another accepted mint | The collector acquires the foreign proofs, then uses that mint to pay a Goats mint quote and claims local proofs. | One donation. Conversion earns zero additional credit. |
| Feed, transfer to Minibits, or approved payout | A confirmed feed consumes feeder credit. A Minibits transfer changes token ownership. A Lightning payout redeems project-owned proofs and reduces the reserve and matching liability. | A feed debits its reserved threshold once. Transfers and payouts earn zero credit. |

Baseline is [main at bd8e09a](https://github.com/lightning-goats/lightning-goats/commit/bd8e09afc25e07393c7485664d6a99b320ff1c33). The [Nut November implementation](cashu-nutnovember-implementation-plan.md) supports ordinary Cashu, nutzaps and Cashu-to-Strike verification. The [September Breez proposal](https://github.com/lightning-goats/lightning-goats/pull/92) is a design reference. This handoff changes the destination of earnings in the proposed Breez mode. Preserve the existing Strike path and its in-flight records. Check current source and host state before acting.

The [HOME and VPS deployment handoff](../deployment/breez-wallet-mint-handoff.md) contains the standalone service packages and the nginx route for `https://mint.lightning-goats.com`.

## 1. HOME wallet

**Assignment:** Build and install a standalone wallet service on `10.8.0.6`. Deliver its source as an isolated package, service definition, configuration sample, acceptance client and restart/restore instructions. Exercise the service independently of the Goats daemon.

- [ ] **Provision one reserve wallet.** Use the operator’s existing Breez SDK Spark application key, a fresh reserve-wallet seed, a dedicated service account and persistent SDK storage. Run one long-lived wallet owner with background sync. Store the service credentials privately and back up its recovery material. The later mint calls this same service. Retain a single writer to the wallet state. Pin and record the tested release. Reference implementation: Breez Spark `0.28.6`. [Treasury configuration](https://sdk-doc-spark.breez.technology/guide/treasury.html) · [SDK source](https://github.com/breez/spark-sdk/tree/0.28.6)
- [ ] **Define the private contract.** Provide health, invoice creation and status lookup. Creation takes a stable operation ID, purpose, whole-sat amount, expiry and either a memo for a normal mint quote or the exact 32-byte description hash for a Goats invoice. The result binds the signed BOLT11, payment hash, wallet/network, amount, expiry and a lookup reference. The local mint funding role also needs fee estimates, bounded invoice payment and outgoing reconciliation. Separate that spending authority from the receive client. Keep admin and recovery local.
- [ ] **Implement verifiable creation and lookup.** The generic Spark SDK receive method uses a text memo. For an invoice with an `h` field, use the matching lower-level `InvoiceDescription::DescriptionHash` call. Disable Spark-over-Lightning fallback for these invoices. Persist the operation intent before provider contact and the signed invoice, payment hash and Spark service-provider receive ID before returning success. Replays with identical inputs return the original result. Conflicts fail. Recover ambiguous creates and sends by original identity, or hold them for review. Verify settlement from the recipient transfer or outgoing wallet record, including amount, actual fee and payment proof as appropriate. [Invoice primitive](https://github.com/breez/spark-sdk/blob/0.28.6/crates/breez-sdk/lnurl/src/routes.rs#L709-L728) · [Receipt polling](https://github.com/breez/spark-sdk/blob/0.28.6/crates/breez-sdk/core/src/sdk/payments/polling.rs#L74-L104)
- [ ] **Prove the private route.** HOME and VPS agents inventory the actual tunnel, peer identities and free ports. Bind to WireGuard or a loopback service behind a private proxy. Use narrow host firewall rules and application authentication such as mutual TLS. Test access from the intended peer and rejection of unauthorized callers. A receive credential cannot pay or export keys. The local mint spends only through its dedicated identity. Preserve the separate feeder-gateway identity and its access to OpenHAB. [Existing topology](../deployment/wireguard-topology.md) · [HOME handoff](../deployment/home-gateway-agent-handoff.md)
- [ ] **Accept independently.** Validate amount, network, expiry, payment hash and exact description hash on a signed invoice. Cover ordinary LNURL metadata and a signed zap request with significant whitespace. Test duplicate, conflict, lost response, reboot and recovery. Fixtures/regtest can exercise state transitions. Breez directs developers to use small mainnet payments for real Lightning send/receive qualification. At an operator-selected time and amount, pay an invoice from an independent wallet, restart and find exactly one settlement. [Breez test environments](https://sdk-doc-spark.breez.technology/guide/testing.html)

**Hand to the mint agent:** exact source revision, wallet identity, endpoint and credential references, method/amount/status definitions, restart/restore results and live checks still pending. Keep sensitive details in the private host record.

## 2. HOME mint and VPS ingress

**Assignment:** Stand up the mint and exercise it using the Stage 1 wallet before modifying Lightning Goats. Establish normal public Cashu operations and the private invoice feature the existing Goats QR needs.

- [ ] **HOME · Issuer and reserve.** Pin a reviewed Nutshell revision or image, starting from `0.22.1`. Generate an independent Cashu signing seed (`MINT_MNEMONIC`). Use a dedicated issuer identity, persistent quote/spent-proof/keyset database, and explicit network, limits and fee policy. Implement a narrow Nutshell funding adapter to Stage 1, following the upstream `SparkL2Wallet` backend for status and fee semantics. Stage 1 owns the Spark seed and data directory. The issuer alone may request reserve spends for authorized melts; it records the original melt quote, invoice, maximum fee and returned change. A public mint funds redemptions even when the stream is offline. [Pinned configuration](https://github.com/cashubtc/nutshell/blob/0.22.1/.env.example) · [Upstream funding backend](https://github.com/cashubtc/nutshell/blob/0.22.1/cashu/lightning/sparkl2.py)
- [ ] **HOME · Project-owned Lightning quote.** Implement an authenticated mint extension for a dedicated collection-wallet quote. Pin its purpose, request ID and the supplied LNURL or zap digest to the existing Nutshell mint-quote lifecycle. Require a collection-wallet claim key using NUT-20 (or demonstrate equivalent exclusive claim authorization). Return the invoice created by the reserve service for that exact quote. The project’s client persists its claim key and planned blinded outputs before exposing the invoice. Ordinary public quotes continue using standard mint methods. The upstream mint passes a text description down to its backend, and its stock Spark adapter drops a supplied description hash. A memo containing the hex digest will produce the wrong signed invoice. Prove this extension against the pinned versions; issue proofs through normal paid-quote accounting. [Nutshell quote creation](https://github.com/cashubtc/nutshell/blob/0.22.1/cashu/mint/ledger.py#L684-L745) · [NUT-04](https://cashubtc.github.io/nuts/04/) · [NUT-20](https://cashubtc.github.io/nuts/20/)
- [ ] **VPS · Public reachability.** Agree on a stable HTTPS URL, e.g. `https://mint.lightning-goats.com`. Terminate TLS on the VPS and proxy supported public Cashu protocol routes over WireGuard. Include `/v1/ws` if advertised. Test DNS, WAF, amount limits and wallet access from outside the tunnel. Keep the private project-quote interface, reserve, management and OpenHAB routes outside public ingress. Public wallet discovery uses the HTTPS name. [Mint capability discovery](https://cashubtc.github.io/nuts/06/)
- [ ] **HOME and independent wallet · Acceptance.** Issue a viewer-owned quote, pay it, claim proofs, swap them and redeem a test amount to an independent Lightning invoice. Separately, have a test collector own a project quote, a different wallet pay it, and the collector claim it. Check exact invoice `h`, paid status, correct owner, lost-claim response and recovery without issuing twice. Add the canonical mint to a separately seeded Minibits wallet, send it Goats ecash, receive it there and verify it can be spent. Keep these tests outside the production Goats ledger and feeder.
- [ ] **HOME · Restore and solvency.** Monitor reserve balance, outstanding issuer liabilities, pending quotes and fees separately. Restore consistent snapshots on an isolated instance and verify wallet identity, keyset ID, a previously spent proof still spent, a known unused test proof redeemable, and a pending quote resolved once. Prevent a second live writer or a stale spent-proof database under the same signing key. If issuance is paused after tokens circulate, preserve holders’ ability to redeem. [Redemption](https://cashubtc.github.io/nuts/05/) · [Proof state](https://cashubtc.github.io/nuts/07/)

**Hand to the application agent:** public mint URL, keyset/capability results, private quote API and owner-binding contract, test invoice/claim outcomes, fee/change behavior, outage recovery and Minibits interoperability results. Report any untested live behavior. A pending custom invoice-hash feature need not block independent mint and Minibits tests.

## 3. Repository and VPS integration

**Assignment:** Keep the six Lightning addresses, both overlay QRs, Nostr receipt signer, NUT-18 HTTP intake, NIP-61 subscriber and existing physical owner. Integrate at the current provider and financial-source boundaries. Use one operator-facing runtime setting.

```toml
wallet_backend = "strike"  # supported: "strike", "breez"
```

- [ ] **Repository · Select new work.** An omitted setting preserves Strike on upgrades. An unknown value or incomplete selected backend fails startup/readiness with an actionable error. Once both backends are provisioned, the same binary switches using this setting and the normal configuration reload/restart. `breez` selects the home wallet-backed mint and Goats-ecash earnings flow. Keep fee limits, authorized mints and existing activation controls independent. Update config parsing, process wiring, systemd credentials, deployment rendering and restore tooling. [Configuration](../../src/config.rs) · [LNURL call site](../../src/lnurl.rs)
- [ ] **Repository · Bind original operations.** Record provider, wallet or mint identity, purpose, custody policy version, stable operation ID and expected payment hash before issuing work. Additive migrations bind historical rows to their original Strike accounts and mint lots. Route callbacks, polling and recovery by the stored binding; enforce global duplicate/payment-hash conflicts across providers. At timeout, resume the original operation. Handle a mix of old Strike-funded and new ecash-funded lots in a single feed without changing their financial rules.
- [ ] **Repository · Lightning and Cashu intake.** For a direct Lightning donation, serve the project-owned Stage 2 quote through the existing Goats callback. Accept only a verified paid invoice and acquired project proofs. Bind those two records to one donation so the Lightning lookup and subsequent proof receipt cannot both grant credit. Preserve NIP-57 signing and raw request bytes. Ordinary mint top-ups and private-contact fees have distinct purposes. For Goats-mint ordinary payments and nutzaps, retain acquired proofs after a successful swap. For approved foreign mints, bind the original acquisition, foreign melt and Goats mint quote together; claim fresh local outputs and reconcile input, fees and change. Guard exposure and make pending conversion visible. Credit acquisition once under existing policy. Mark its lot eligible for the new custody path when local ownership is verified; permit independently funded lots to proceed during an outage. [Native zap contract](../architecture/native-nip57.md) · [Current settlement worker](../../src/cashu/treasury_worker.rs)
- [ ] **Repository · Feeding and earnings.** Replace the old pre-dispatch Cashu-to-Strike rule only for new Breez-mode lots. Freeze a source allocation against verified Goats-mint holdings, then let the existing owner dispatch and confirm the same physical UUID. A successful feed consumes entitlement and releases the appropriate project earnings for disposition. Keep auditable reservations for pending feeds, CyberHerd obligations, fees and transfers. Proofs are fungible; ensure the same project value cannot be allocated twice. A feed does not require a melt, a transfer to the phone, or the phone to be online. Unknown physical outcomes retain their original reservations and UUID. [Existing wallet and feed invariants](../architecture/cashu-wallet-boundary.md)
- [ ] **Repository · Minibits and payouts.** Provide an operator-only transfer of available project-owned Goats ecash to a Minibits receiving request scoped to this mint. Reserve a specific amount, track original proofs and returned change, and reconcile ownership on retry. An ambiguous handoff stays pending until the original transfer’s disposition is known. Transferring a token between these wallets adds zero credit and preserves total issuer liability. Use the separate payout authority for authorized CyberHerd Lightning payments. Reserve spendable project proofs and melt against the recipient’s invoice with the existing fee caps, verification and retry rules. Keep cashu-derived rewards subject to their explicit authorization policy. Maintain legacy payout recovery, private-contact fee delivery and provider-specific records. [Payout provider](../../src/payout/provider.rs) · [Reward funding](../../src/ledger/reward_funding.rs)
- [ ] **VPS · Stage and test the same build with both settings.** Run the existing Strike suite with default and explicit selection. Exercise the six addresses, zap verification, operator transfer, both Cashu inputs, cross-mint fees/change and mixed old/new lots. Reuse the 600-sat Lightning + 250-sat net nutzap + 150-sat net ordinary Cashu example at a 1,000-sat threshold. In Breez mode expect one donation per input, one confirmed simulated feed, zero extra credit for mint funding/conversion, and zero feed-triggered Lightning withdrawals. Test stale events, a WireGuard interruption after payment, restart after claim or proof handoff, and changing the selector with old work pending. Test a shared mint whose reserve also backs an unrelated viewer’s balance. An operator withdrawal must leave that balance redeemable. [Existing scenario fixture](../testing/cashu-two-mint-settlement-20261117.json)

Report separate totals for incoming contributions, fees, outstanding credit, project-owned proofs, reserved obligations and operator-accessible earnings.

## 4. VPS cutover and rollback

1. **VPS** inventories outstanding invoices, treasury operations, payout reservations and physical attempts. Quiesce writers for a verified pre-migration backup. **HOME** confirms sync, restore readiness, issuer liabilities and redemption availability. Stage the candidate build with Strike selected.
2. **Operator/VPS** choose a switch window and a bounded mainnet test. Set `wallet_backend = "breez"` and apply the configuration to participating roles. Route new work through the home mint. Retain original Strike reconciliation for unpaid-but-valid invoices, late events, unresolved melts and payouts.
3. **VPS/HOME** reconcile one Lightning donation, one ordinary Cashu payment and one nutzap through normal interfaces. Verify a single physical feed when scheduled, unchanged holdings across feeding, a transfer to Minibits with no duplicate credit, and an independently verified authorized payout. Compare collected ecash and actual fees to wallet/mint records. Keep the reserve solvent for every holder.
4. **Rollback** by selecting `strike` for new work. Finish prior Breez quotes, claims, payouts and transfers under their original identities. Preserve all paid history and outstanding ecash redemption. Retire Strike credentials after original work is terminal or explicitly accounted for. Keep any legacy balance transfer separately recorded with zero new feeder credit.

Each agent should report its host role, exact version, tests actually run, result, open items and next owner. Keep private keys, recovery phrases, bearer proofs, unclaimed quote secrets and identifiable payment records in private host storage.
