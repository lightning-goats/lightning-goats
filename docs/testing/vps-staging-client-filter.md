# VPS staging client policy transition

Production HOLD. This is a parameterized candidate and isolated TCP regression,
not an executable approved network manifest. Private endpoint, peer keys,
namespace inventory and recovery agreements remain outside GitHub. PR65 covers
the home policy; PR62 provides isolated peer binding evidence. Neither alone
proves the complete two-host policy.

The nft example replaces only an inventoried project table inside a dedicated
client namespace. It allows loopback, outbound TCP to the gateway and correlated
established replies; forwarding and all other traffic, including established
SSH/Hexmem sessions and IPv6, are dropped. Render placeholders from the approved
private manifest, verify the exact baseline and other rules, and syntax-check
before the atomic delete/add transaction. Never apply this in the host namespace
or substitute a household/host-manager table.

The separate staging manifest must specify encrypted UDP transport, reciprocal
specific peer mappings and runtime transport firewall ownership. A listening
UDP socket does not prove new peers can reach it. This change creates no real
endpoint, route, peer, host allow or application startup.

The test uses two fresh veth namespaces and real TCP echo servers. It verifies
inspection access before transition, gateway denial, then closure of both
established and new inspection flows with successful gateway traffic. Restoring
the synthetic baseline restores inspection and blocks gateway again. No
WireGuard or live host is involved. Strict Bash and JSON validation prevent
pipeline-masked failures. Local execution passed on 2026-09-13 after correcting
a synthetic baseline statement-separator error; no host table was changed.

Before application, HOME and VPS must ACK endpoint/key/mapping, independent
recovery, snapshots and persistence in the private manifest. Closing inspection
ends that communication path; use the approved GitHub rendezvous. Keep canary
exposure closed until both policies and a fresh authenticated handshake pass.
Explicit operator network and harmless-test approval is required.

Rollback closes the home listener and stops the synthetic daemon before removing
identity bindings or restoring inspection policy. Preserve both stores and
unresolved requests; verify exact resources before removing only session-created
additions. Isolated table rollback is not permission to remove a real peer while
the canary remains exposed. Combined two-host and restart/persistence acceptance
remain open.
