# Independent request parser compatibility

This development harness uses unmodified **Cashu-TS 4.7.2** and four exact-version
dependencies, locked by archive SHA-512 in `packages.json`. This package is a test
fixture, not part of the production core/wallet dependency graph. All downloaded
packages declare MIT; their original license files remain in the temporary
extraction. No downloaded package scripts execute. Node 22.23.1 was used locally.

Prepare dependencies in a new temporary directory (network required), then run
the parser without network access:

```sh
python3 tools/cashu-client-compat/prepare.py /tmp/lg-cashu-ts-test
node tools/cashu-client-compat/verify-requests.mjs /tmp/lg-cashu-ts-test tests/website/fixtures/cashu-requests.json
```

For isolated execution, use the repository's approved fresh-network-namespace
harness convention and an unprivileged identity. The verifier also refuses global
`fetch`. This test never constructs a funded wallet, calls a mint or delivers a
payment. It checks descriptor identity, no fixed amount, sat unit, reusable flag,
exact configured mint list, description and POST destination. Package archives
must be treated as code; the preparation script verifies integrity, rejects
redirects and unsafe archive members, and bounds compressed/uncompressed size.

The initial isolated result is a deliberate recorded failure:
[Cashu-TS compatibility evidence](../../docs/testing/cashu-ts-request-initial-20261116.json).
Both generated `creqB` requests parse correctly. Both original CDK `creqA`
requests fail because CDK serializes absent amount as CBOR `a:null`, while this
independent parser expects the field to be absent. Corrected request generation
and new native/browser/parser qualification remain required. Do not alter fixture
strings by hand or label this partial result as full sender compatibility.

Passing parser tests will establish only library-level request interoperability.
Real sender payment, repeated POST/lost reply, browser CORS/WAF and phone scans
remain separate requirements in the implementation plan.

A standalone diagnostic correction is now recorded in
[candidate parser evidence](../../docs/testing/cashu-ts-request-candidate-20261116.json).
It uses the exact pinned Cashu/ciborium libraries, removes only the null CBOR `a`
entry, requires no `a` key in the encoded result, and verifies exact typed CDK
round-trip equality. Cashu-TS parses all four resulting candidates offline.
These candidate bytes were not generated by a rebuilt wallet CLI; integrating the
encoder correction and regenerating/requalifying native output remain required.

CI's wallet job now invokes the preparation script, combines its short/long
fresh native CLI results using `combine-native.py`, and runs the independent
parser in an unprivileged fresh network namespace. It retains parser output and
native input as artifacts. Local workflow/shell syntax and combination checks
pass; see [CI preparation evidence](../../docs/testing/cashu-ts-ci-preparation-20261116.json).
No remote CI run is claimed. The check intentionally still fails against the
current native `creqA` output until the encoder correction is integrated; the
standalone candidate passing result does not bypass this gate.

The correction is now integrated and the rebuilt native CLI passes both fixture
configurations. Its [actual native output](../../docs/testing/cashu-request-corrected-native-20261116.json)
passes all four independent parser cases and all 44 website browser cases.
Canonical fixture replacement waits for integrated Rust/transport acceptance;
use the evidence's regenerated fixture input until that guarded step completes.
The earlier statements above describe the recorded initial/candidate checkpoints.
Real sender payments and phone scans remain unqualified.

## SDK-assisted ordinary payment fixture

The composed HTTP runner now has an optional `--cashu-ts-sender` mode. It uses
`send-fixture.mjs` in a separate unprivileged Node process with the same UID as
the wallet fixture. Cashu-TS parses the actual advertised native descriptor,
loads the synthetic mint's public keychain cache, and selects exact existing
DLEQ-bearing proofs through `Wallet.sendOffline`. Payload encoding uses SDK
`JSONInt.stringify`, preserving integer representation. No sender mint RPC is
allowed. The fixture maps the advertised HTTPS endpoint to the isolated local
HTTP service; TLS is not qualified.

The sender checks OPTIONS/CORS and POST with an Origin header, deliberately
discards the first admission body, then repeats the POST and requires a stable
capability. The existing native fixture continues actual CDK acquisition,
receipt import, treasury settlement, status and consumed-credit replay checks.
Both normal and lost-melt-reply modes pass
([evidence](../../docs/testing/cashu-sdk-sender-20261116.json)). This is independent
library interoperability, not qualification of an end-user wallet application,
real browser/phone, live mint/provider/relay, or physical feeding.

Preparation now emits `package-files.json` after verifying archive SHA-512.
Pass its SHA-256 explicitly as `--sender-files-sha256`, along with
`--sender-installation` and `--sender-node`. The runner copies only the exact
file inventory, requires the repository package lock, checks package identities,
and refuses changed, missing/unlisted, aliased or special files. Copied code is
root-owned/read-only in the privileged fixture and executes only under the
disposable wallet UID. Six copy-boundary tests pass. Package contents remain
outside the source tree.
